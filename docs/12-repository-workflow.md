# 12. Работа с репозиторием GitHub

## Назначение репозитория

Весь проект хранится в GitHub-репозитории.

Репозиторий содержит:

- документацию;
- конфигурационные шаблоны;
- вспомогательные скрипты;
- структуру проекта.

Использование Git позволяет:

- отслеживать изменения;
- безопасно обновлять документацию;
- переносить проект на другой VPS;
- хранить историю изменений;
- совместно работать над проектом.

---

## Что хранить в GitHub

В репозиторий рекомендуется помещать только те файлы, которые безопасно публиковать.

Например:

- Markdown-документацию;
- шаблоны конфигураций;
- примеры настроек;
- скрипты установки;
- изображения;
- схемы;
- файлы MkDocs.

---

## Что нельзя хранить в GitHub

Никогда не публикуйте:

- приватные ключи AmneziaWG;
- SSH-ключи;
- пароли;
- токены;
- реальные IP-адреса клиентов;
- файлы резервных копий;
- экспортированные конфигурации клиентов.

Даже если репозиторий приватный, секреты рекомендуется хранить отдельно.

---

## Клонирование проекта

При первом развёртывании проекта используется обычное клонирование репозитория.

```bash
git clone https://github.com/mannaro/amneziawg-selfhost.git
```

После этого необходимо перейти в каталог проекта.

```bash
cd amneziawg-selfhost
```

---

## Обновление проекта

Если репозиторий уже существует локально, повторное клонирование не требуется.

Достаточно выполнить:

```bash
git pull
```

Git скачает последние изменения и обновит рабочую копию проекта.

---

## Работа через HTTPS и SSH

GitHub поддерживает два основных способа подключения.

### HTTPS

Используется адрес вида:

```text
https://github.com/mannaro/amneziawg-selfhost.git
```

Для выполнения `git push` потребуется аутентификация. Это может быть Personal Access Token (PAT), Git Credential Manager или SSH-ключ.

---

### SSH

Используется адрес вида:

```text
git@github.com:mannaro/amneziawg-selfhost.git
```

При наличии настроенного SSH-ключа дополнительная авторизация обычно не требуется.

---

## Перенос проекта на другой VPS

Одним из главных преимуществ использования Git является возможность быстро восстановить структуру проекта на новом сервере.

Для этого достаточно:

1. Создать новый VPS.
2. Установить Git.
3. Клонировать репозиторий.
4. Перейти в каталог проекта.
5. Восстановить резервную копию секретов.
6. Продолжить настройку по соответствующим главам документации.
7. Проверить работоспособность сервера.
8. Обновить DNS при необходимости.
9. Проверить подключение клиентов.
10. Убедиться в корректной работе маршрутизации.
11. При необходимости выполнить финальную настройку.
12. Отключить старый сервер после проверки нового.

После клонирования репозитория дальнейшая настройка выполняется по соответствующим главам документации.

Такой подход позволяет полностью восстановить структуру проекта даже при отсутствии доступа к старому VPS, если сохранена резервная копия секретов и конфигурации.

---

## GitHub и резервные копии

GitHub не заменяет резервное копирование.

Эти инструменты решают разные задачи.

GitHub хранит:

- документацию;
- структуру проекта;
- историю изменений;
- шаблоны файлов.

Резервная копия должна содержать:

- ключи AmneziaWG;
- клиентские конфигурации;
- секреты;
- экспортированные настройки;
- важные пользовательские данные.

Использовать рекомендуется оба подхода одновременно.

---

## Полезные команды Git

Проверить состояние репозитория:

```bash
git status
```

Посмотреть историю:

```bash
git log --oneline
```

Получить последние изменения:

```bash
git pull
```

Получить изменения без объединения:

```bash
git fetch --all
```

Отправить изменения:

```bash
git push
```

---

## Рекомендуемый рабочий процесс

При работе над проектом удобно придерживаться следующей последовательности.

1. Внести изменения.
2. Проверить результат локально.
3. Выполнить:

```bash
git status
```

4. Добавить изменённые файлы:

```bash
git add .
```

5. Создать коммит:

```bash
git commit -m "Краткое описание изменений"
```

6. Отправить изменения:

```bash
git push
```

После публикации GitHub Pages автоматически обновит сайт.
